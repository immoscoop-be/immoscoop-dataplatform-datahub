An Application asks to read your Resources. The Agents' portal wants Leads per agency, of Sales, through two Feeds of the Dock Agents' portal. Read what leaves and who sees it, then say yes or no.

We are building the new Agents' portal with IT: each agency follows its own leads, views and response time, per month and per week. Leads per agency is the heart of it.

2Who reads

Users of the user pool Agencies, of AWS Cognito, kept by IT: the agents of every agency that signs in to the portal. Data Hub checks the token of each user against that pool, and answers only with their slice.

3The Binding Rule

An agent sees only the rows of their own agency: company_id of the Feed equals the company_id of their agency in the user pool Agencies.leads.company_id = agencies.company_id

For one user: an agent of agency 1042 sees only the rows where company_id is 1042, never those of another agency.

The same rule for both Feeds. Data Hub has no rights per row: the rule slices only what this Application gets.

6How often

Daily. Both Feeds are delivered once a day, after a run of their Resources succeeded.

7Prepared or live

Prepared. The portal reads a copy that Data Hub fills after a run that succeeded, never BigQuery itself. When a run fails, or a Rule of an Owner holds it, it keeps the last good delivery, with its date. An external Application always reads prepared.
