# query

| | |

**In one sentence:** query is the only service that reads the tables of the Resources: it runs the queries of Query, the previews of Resources and the Lenses, and keeps them in the Query Log, and later runs free SQL for Claude and serves feeds to Excel, always only over Resources the User may see.

## How a query is checked

Its service account may read every table of the project ([DEC-SR-32](../../requirements/functional/04-stacks-and-resources.md#dec-sr-32)), so query decides what a query reads, in its Pre-flight and again before every run ([TR-SR-15](../../requirements/technical/04-stacks-and-resources.md#tr-sr-15)):

1. query asks catalogue, with the token of the User, for each Resource of the query: whether the User may see it, its Key, the full name of its table in its own case, which is what BigQuery is asked for ([DEC-SR-44](../../requirements/functional/04-stacks-and-resources.md#dec-sr-44)), its fields and how it is stored.
2. It puts the functions of the Parameters into the SQL in place of their `@names`, and reads the tables named in it: each must be one of those Resources. Every `@name` must be a Parameter.
3. A dry run in BigQuery, with each Resource named by its full name in its own case ([DEC-SR-44](../../requirements/functional/04-stacks-and-resources.md#dec-sr-44)), says what the query reads at most, that it only reads (`SELECT`), and which tables it reads: those Resources, or the tables beneath them.
4. The bytes give the range: up to 100 MB it runs, up to 1 GB its author approves it, above it goes to the Data Team. Without a filter on the partition column of a Resource that requires one, it does not run ([TR-SR-16](../../requirements/technical/04-stacks-and-resources.md#tr-sr-16)).
5. It runs as a job with a maximum on the bytes billed, the values of the Parameters as named query parameters, and labels with the User and its Query ID; the pages of its result are read from that job. Above 1 GB it runs only once the Data Team accepted a Request of its author ([TR-SR-18](../../requirements/technical/04-stacks-and-resources.md#tr-sr-18)).

## Data

The schema `query` ([DEC-PF-29](../../requirements/technical/00-platform.md#dec-pf-29)): `queries`, one row per query with its Resources as they were named when it was made, the SQL and Parameters being written and where it started, and `runs`, the Query Log, one row per run with the SQL and values it ran with ([TR-SR-17](../../requirements/technical/04-stacks-and-resources.md#tr-sr-17)); the Parameters and where a query started came in migration `0002-parameters`, and in `0003-previews` the kind of a query, `query` or `preview`, one preview query per User and Resource, and the purpose of a run, `run` or `values`, each numbered apart; in `0004-lenses` the Lenses and their versions, and the kind `lens`, one query per User and Lens for its runs ([TR-LE-01](../../requirements/technical/09-lenses.md#tr-le-01)); in `0005-lens-upkeep` a stopped Lens, what a Broken Lens misses, the Log of a Lens (`lens_log`), and on a query the Lens it is used as after "Open in Query" and the Collection whose "New Lens" started it ([TR-LE-04](../../requirements/technical/09-lenses.md#tr-le-04) to [TR-LE-06](../../requirements/technical/09-lenses.md#tr-le-06)); in `0006-lens-words` the extension `unaccent`, in `public`, and the text search configuration `lens_words`, English without accents ([TR-LE-07](../../requirements/technical/09-lenses.md#tr-le-07)). In `0007-lens-decisions` a Lens the Data Team refused, `refused`, and their decisions in its Log, `LEN-001` and `LEN-002` ([TR-CV-02](../../requirements/technical/14-conversations.md#tr-cv-02)). The Requests to the Data Team are Messages of catalogue. The Data Team reads it in Cloud SQL Studio ([TR-PF-28](../../requirements/technical/00-platform.md#tr-pf-28)). Its migrations are in `services/query/src/migrations`. The queries a User hid from their panel are in `hidden_queries`, migration `0008-hidden-queries` ([DEC-UX-138](../../design/principles.md#dec-ux-138)). In `0009-broken-queries` what a Broken query misses (`queries.broken`), its SQL and Parameters as last checked, for a dry run without its User (`check_sql`, `check_parameters`), and the Log of a query (`query_log`) ([TR-SR-23](../../requirements/technical/04-stacks-and-resources.md#tr-sr-23)).

## Talks to

BigQuery, in the project and location of Data Hub (`DATAHUB_BIGQUERY_PROJECT`, `DATAHUB_BIGQUERY_LOCATION`), and catalogue (`DATAHUB_CATALOGUE_URL`), with the token of the User: for the Resources of a query, the Collections the User sees and the Resources in them, whether the User manages a Collection, and to send and read the Requests on queries and Lenses. Besides its queries, it reads the metadata of tables and `INFORMATION_SCHEMA.PARTITIONS`, which read no data. Cloud Scheduler calls it once a day to check every Lens and query, with a Google ID token of `datahub-scheduler` for its own address (`DATAHUB_QUERY_URL`, `DATAHUB_SCHEDULER_SERVICE_ACCOUNT`), and catalogue after a new Current Version, with its own (`DATAHUB_CATALOGUE_SERVICE_ACCOUNT`) ([TR-SR-23](../../requirements/technical/04-stacks-and-resources.md#tr-sr-23)). It tells catalogue as itself, with a Google ID token for catalogue's address, what decides who sees the Messages on each Lens, the Request of Data Hub on a Lens that stopped, that a Lens grew into large ([MSG-LEN-02](../../requirements/functional/message-catalogue.md#msg-len-02)), that a query or a Lens became Broken or works again ([MSG-QRY-02](../../requirements/functional/message-catalogue.md#msg-qry-02), [MSG-LEN-05](../../requirements/functional/message-catalogue.md#msg-len-05)), and the decision of the Data Team on a Request on a Lens ([TR-CV-02](../../requirements/technical/14-conversations.md#tr-cv-02)): when a Lens changes, when query starts, and in the daily check.
