Every type of Message in Data Hub, between the four actors: a User, the Owner of an object, the Data Team, and Data Hub itself ([DEC-CV-07](14-conversations.md#dec-cv-07), [FR-CV-10](14-conversations.md#fr-cv-10)). For each, the catalogue says who sends it to whom and when; its texts, plain and laid out, in Dutch and English ([FR-CV-11](14-conversations.md#fr-cv-11), [FR-CV-12](14-conversations.md#fr-cv-12)); the Learning Card that explains it ([FR-CV-14](14-conversations.md#fr-cv-14)); and what it asks of whoever receives it, with the buttons that link the Message to that action ([FR-CV-13](14-conversations.md#fr-cv-13)).

The catalogue itself is code, in [`packages/contracts/src/messageCatalogue.ts`](../../../packages/contracts/src/messageCatalogue.ts): the web app takes its texts from there, and so will Slack and the MCP server ([FR-CV-15](14-conversations.md#fr-cv-15)). A test checks it: the same parameters in both languages and both layouts, a value for every placeholder, and every example filled in. A Message ID, such as `MSG-RES-02`, is fixed: never renumbered or reused. It is neither a requirement ID nor a Log ID of the [Log catalogue](log-catalogue.md).

## How to read it

- **From and to.** A Message is placed on its object, never sent to a person ([FR-CV-03](14-conversations.md#fr-cv-03)); "to" are those who get a notification of it. The Owner is who answers for the object: the Owner Unit of a Collection, a Resource or a Lens, who made a query, the Data Team for a Learning Card.
- **Kind.** What the Message Centre filters on ([FR-CV-06](14-conversations.md#fr-cv-06)): a Question, Remark, Signal or Request, a reply, a decision on a Request, a notice the Owner sends through a form, or what Data Hub writes itself.
- **Plain** has no formatting at all, for a notification, the fallback of a Slack message or a screen reader; its first line stands alone, as the line of the Message in a list. **Laid out** uses a small part of Markdown that every channel can render: paragraphs, `**strong**`, `~~struck~~` for a text that was replaced, `` `code` `` for a name, `- ` for an item and `> ` for the words of a person.
- **Placeholders** are `{name}`, filled in when the Message shows, so that a name is always current. Every Message has `{subject}` and `{subjectKind}`, its object; one written by a person also `{writer}` and `{text}`, their words. `{name, select, …}` and `{name, plural, …}` choose words, as in the ICU message format. A line that holds an empty optional value is left out. Counts, sizes and dates are written as each language writes them; a name is never translated ([NFR-LOC-01](../non-functional/localisation.md#nfr-loc-01)).
- **The object** is not a parameter of the text alone: wherever a Message shows, it carries its object with its icon and current name, and links to it, opening in context ([FR-CV-02](14-conversations.md#fr-cv-02), [FR-CV-09](14-conversations.md#fr-cv-09)). What Data Hub writes itself shows its Learning Card under its text, in "Understand what is happening here" ([FR-LR-38](16-learning.md#fr-lr-38)).
- **Learning Card.** *Named* by a requirement or a decision; *Proposed*, a card of the master learning plan that fits, to confirm; *To write*, no card fits yet, and one is written before the Message is built ([FR-LR-38](16-learning.md#fr-lr-38)); *By the writer*, a person writes the Message and may add a card to it ([FR-LR-07](16-learning.md#fr-lr-07)).
- **What it asks.** Nothing, an answer, a decision, or something to do; of whom; the buttons that take the receiver there; what ends it; and the states of the Message while it asks something, where it starts and where it can end.

**Learning Card:** By the writer. Whoever answers can add the card that explains the answer ([FR-LR-07](16-learning.md#fr-lr-07)).

**Dutch, laid out**, with the example:

> **Karel Leys** stelde een vraag over de lens Leads per source name

**Dutch, plain:**

```text

```

**English, laid out**, with the example:

> **Karel Leys** asked a question about the lens Leads per source name
>
> > Mailing brings only 3.8% of the leads this year; last year it was close to 10%. Did something change in how mailing leads are tagged?

**English, plain:**

```text

```

### MSG-CNV-03 · Signal

| | |
| --- | --- |
| Kind | Signal |
| About | Resource or Lens |
| From → to | User → Owner and Data Team |
| When | A User reports that something seems odd about the data of a Resource or a Lens, from "Messages" on its page. |
| Status | Specified |
| Comes from | [FR-SR-30](04-stacks-and-resources.md#fr-sr-30), [FR-CV-03](14-conversations.md#fr-cv-03), [FR-CV-07](14-conversations.md#fr-cv-07) |
| Open points | [OP-SR-14](04-stacks-and-resources.md#op-sr-14) |

**What it asks:** Something to do, of the Owner and Data Team. The Owner and the Data Team look into it. Either replies with what they found, or makes it an Anomaly on the Resource Card, which then holds it ([FR-SR-30](04-stacks-and-resources.md#fr-sr-30)).

**How it ends:** A reply answers it; made an Anomaly, it links to the Anomaly. Either notifies its writer. It starts `open` and ends `answered` or `anomaly`.

| Button | Opens | For |
| --- | --- | --- |
| Open in context · *Openen in context* | The page of its object as it is, with the Message in a floating window over it ([FR-CV-09](14-conversations.md#fr-cv-09)) | every recipient |
| Make it an anomaly · *Maak er een anomalie van* | The Known Behaviour of the Resource, with a new Anomaly filled in from the Signal ([OP-SR-14](04-stacks-and-resources.md#op-sr-14)) | Owner and Data Team |

**Learning Card:** By the writer. Whoever answers can add a card; for a Signal that turns out to be no error, K4.4 Reporting an error or a doubt explains the way.


> **Karel Leys** gave a signal: something seems odd in the data of the resource Weekly lead volume
>

**English, plain:**

