## Requirement

> Claude kan de semgraph gebruiken via een MCP-server op `POST /mcp` (Streamable HTTP, zonder toestand), in
> dezelfde container en op dezelfde kern als de REST-API. De tools: `list_semgraphs`, `describe_semgraph`,
> `validate_semgraph` en `render_semgraph`; alle tools zijn read-only. Voor Claude Code ook lokaal (stdio) vanuit
> de repository.

## Zo geïmplementeerd

- **Dezelfde kern.** Elke tool roept aan wat REST ook aanroept: het overzicht en de beschrijving van een semgraph
  (`src/core/catalog.ts`, gedeeld met `GET /semgraphs`) en de pipeline (`runPipeline`). Niets staat er twee keer:
  de tool-schema's komen uit JSON Schema (`fromJsonSchema`), zonder zod.
  - `list_semgraphs {locale?}`: wat `GET /semgraphs` geeft.
  - `describe_semgraph {id, locale?}`: wat `GET /semgraphs/{id}` geeft, plus het eerste voorbeeld volledig, als
    vertrekpunt. Een geplande semgraph geeft de melding `plannedSemgraph`.
  - `validate_semgraph {request}`: het rapport van `POST /validate`, met de afwijkingen en de versies.
  - `render_semgraph {request}`: tekent; zie [REQ-092](REQ-092.md) voor wat Claude en de gebruiker krijgen. Een
    weigering is een antwoord (met het alternatief), een ongeldige aanvraag een fout om te herstellen.
  - Het invoerschema van `request` is los (een object met `semgraph`): zo blijft `tools/list` klein, en de
    pipeline controleert het contract en antwoordt in gewone taal.
- **De uitleg voor Claude** (de `instructions` van de server) deelt zijn zinnen met de OpenAPI-beschrijving
  (`src/core/guide.ts`): kies op betekenis, reken in het warehouse ([REQ-058](REQ-058.md)), leeg is geen nul, en
  vul `meta` ([REQ-093](REQ-093.md)).
- **Zonder toestand.** Elke `POST /mcp` krijgt een eigen server, zonder sessie, en het antwoord is gewone JSON, geen
  event stream: niets moet blijven openstaan door CloudFront. `GET` en `DELETE` geven 405.
- **Transport.** De web-standaard transport van `@modelcontextprotocol/server`, niet de Node-adapter: die sluit de
  socket een halve seconde na het antwoord als Fastify de body al las, en dat zou keep-alive-verbindingen breken.
- **Logging.** Zoals REST één regel per aanvraag (`semgraph.mcp.render`, `semgraph.mcp.validate`): semgraph,
  uitkomst en codes, nooit datawaarden en nooit wie het vroeg.
- **Lokaal.** `npm run mcp` start dezelfde server op stdio; `.mcp.json` geeft hem aan Claude Code in een clone van
  deze repository, zonder login. Daar schrijft `render_semgraph` elke grafiek ook naar `out/mcp/`, want Claude Code
  toont geen app.

## Code en tests

- `src/mcp/server.ts` (`createMcpServer`), `src/routes/mcp.ts`, `src/mcp/stdio.ts`, `.mcp.json`,
  `src/core/catalog.ts`, `src/core/guide.ts`, `src/core/log.ts`.
- `test/mcp.test.ts`: vier read-only tools; `list_semgraphs` en `describe_semgraph` geven wat REST geeft;
  `validate_semgraph` het rapport van `/validate`; weigering en ongeldige aanvraag; 405 op GET en DELETE.
- `test/requirements.test.ts`, de test "REQ-090": elk voorbeeld van elke semgraph krijgt via MCP dezelfde uitkomst,
  dezelfde meldingen en dezelfde SVG als via de kern.
- CI (`.github/workflows/ci.yml`): de container met `MCP_AUTH=none` geeft zijn tools.
