## Requirement

> De server beschrijft zijn API als OpenAPI-document (Swagger), zodat een andere toepassing of een agent in de
> cloud weet hoe ze de dienst gebruikt: `GET /openapi.json`, en Swagger UI op `/docs` om het te lezen en uit te
> proberen.

## Zo geïmplementeerd

- **Eén bron.** Het document wordt bij de start opgebouwd uit wat er al is: het contract van elke semgraph
  (`schema.json`, JSON Schema 2020-12, dat OpenAPI 3.1 neemt zoals het is) en haar voorbeelden. Een nieuwe semgraph
  of een gewijzigd contract staat er dus vanzelf in.
- **`POST /render` en `POST /validate`** nemen een `RenderRequest`: één van de contracten, gekozen op `semgraph`
  (`oneOf` met een `discriminator`). Elk voorbeeld staat erbij, zodat "Try it out" in Swagger UI meteen een grafiek
  geeft. De antwoorden zijn beschreven: de SVG met de headers `Semgraph-*`, en het rapport (`Report`, `Issue`) bij
  400, 413, 415 en 422.
- **De beschrijving bovenaan** zegt hoe je de dienst gebruikt: kies een semgraph (`GET /semgraphs`), reken de blokken
  in het warehouse ([REQ-058](REQ-058.md)), valideer en teken; leeg is geen nul. Zo weet ook een agent wat hij moet
  doen.
- **Swagger UI** op `/docs` (met `@fastify/swagger` in static mode en `@fastify/swagger-ui`): het document is van
  ons, de plugins tonen het enkel. Swagger UI zit in het pakket en laadt niets van buiten, onder een eigen strenge
  CSP (geen validator, geen upgrade naar https, zodat het ook op een interne http-host werkt). `/docs/json` geeft
  hetzelfde document.
- **Vindbaar:** `GET /semgraphs` geeft `openapi` en `docs` mee, en de galerij linkt naar `/docs`.
- `security: []`: de dienst heeft geen eigen login; toegang regelt het platform ervoor.
